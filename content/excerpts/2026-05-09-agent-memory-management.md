## 背景

本文来自公众号 CppMore，系统讲解了 Agent 框架中记忆管理的设计原理，涵盖短期记忆、长期记忆和治理策略三个核心模块，并结合 Wuwe Agent Framework 给出了 C++ 实现示例。

## 核心观点

- **记忆管理是 Agent 智能化的基础**：Agent 的智能程度取决于它对上下文的掌握 — 记什么、怎么记、何时记、如何取，构成记忆管理机制的四大关键问题
- **短期记忆维持对话连续性**：因为 LLM 每次 API 调用都是独立的，必须手动保存上下文（对话消息、任务状态、历史摘要），并在预算控制下注入请求
- **长期记忆需要显式写入**：长期记忆只保存稳定、可复用的信息（用户偏好、项目事实、决策约束等），默认不自动写入，避免污染和安全隐患
- **治理策略是产品化的前提**：信息隔离（跨用户不串）、敏感过滤（API key/密码不入库）、TTL 过期清理、操作审计追踪，缺一不可

## 补充要点

- 短期记忆三类：对话消息、任务状态、历史摘要，需做预算控制避免上下文膨胀
- 长期记忆存储 = SQLite（完整内容）+ 向量数据库（语义索引），语义索引是派生数据，丢失可重建
- 语义搜索解决的关键问题：表达方式不同但意思相同的查询，常规数据库无法匹配
- 向量数据库召回流程：Qdrant 语义搜索 → SQLite 取完整记录 → 过滤/排序 → 注入 Prompt
- 框架默认不自动写长期记忆是产品策略，自动写入可能产生副作用和安全隐患
- Wuwe Agent Framework 用 C++ 实现，短期记忆通过 memory_policy 控制窗口大小
