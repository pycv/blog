## 背景

机器之心报道了 X 平台上的一场争论：AI Agent 写代码越来越快，开发者到底还要不要逐行审查？《代码整洁之道》作者 Robert C. Martin（Uncle Bob）给出了最激进的答案——完全不看。

## 核心观点

- **Uncle Bob 的激进策略**：完全不阅读 Agent 写出的任何一行代码。与之对应的是极严格的自动化约束——单元测试、Gherkin 测试、QA 流程、变异测试、覆盖率指标等多重关卡。
- **信任模式的转变**：从依赖人工阅读代码找漏洞，转向工业式的质量管理——先定义规格和验收条件，再用自动化持续验证。两种信任方式本质不同。
- **审查并未消失，只是上移了**：Uncle Bob 仍然亲自审查 Gherkin 验收测试、QA 流程，并进行最终的人工测试验收。关键功能全面审查，普通功能抽查。只是不再逐行读实现代码。

## 补充要点

- 反对者的核心焦虑：如果我要对这段代码负责，我必须理解它——这是心理上绕不过去的坎。
- 更大的风险在于：Agent 可能擅自修改测试让结果适配实现，或者测试全绿但需求理解本身就错了。AI 不会让这些问题消失，反而因为代码生成更快而更难发现。
- 有开发者提出中间路线：逐行读所有依赖成本太高，完全放弃审查又太激进。重点应是哪些代码必须审、审到什么程度、哪些环节可以自动化。
- 一个更超前的追问：当 AI 让代码的生成和修改成本大幅下降，代码本身的质量还像过去一样重要吗？如果 Agent 可以随时重写模块，代码是否优雅似乎没那么关键了。
- Uncle Bob 的实际做法：Agent 写的单元测试不审，但 Gherkin 测试和 QA 流程仍由他亲自检查，强度取决于项目风险。
